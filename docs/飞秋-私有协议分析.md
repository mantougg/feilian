# 飞秋私有协议分析

> 来源：云桌面真机抓包（feilian.log 完整样例）+ 开源实现对照
> [compilelife/feiq](https://github.com/compilelife/feiq)（feiqlib/feiqcommu.cpp）、
> [blisssayyid/feiX](https://github.com/blisssayyid/feiX)（README 逐字段分析）、
> [和飞秋的通讯实现](https://www.cnblogs.com/vir56k/archive/2011/07/11/2103378.html)（标准 IPMsg 侧）。
> 状态：格式结论已实锤；待真机复核项见 §8。

## 1. 结论摘要

**飞秋私有格式不是另一套协议，而是标准 IPMsg 冒号 6 段格式的超集**：

```
version:packetNo:用户名:主机名:命令字:附加段
```

唯一区别是 `version` 字段本身被飞秋塞进了 `#` 分隔的私有头（内含 MAC 地址，用于自环过滤）。
标准解析器（SplitN ':' 切前 5 项）之所以失败，是因为 packetNo 段是毫秒时间戳没有问题，
而是 **version 段内的 `#` 不影响冒号切分——真正让标准解析失败的是飞秋把字段顺序/内容
做了扩展**（详见 §5 实拍对照）。命令字用**十进制**书写且常带非标准选项位组合。

## 2. 私有头（version 字段）结构

feiq 源码 `feiqcommu.cpp` 构造模板（逐字引用）：

```cpp
mVersion = "1_lbt6_0#128#"+mMac+"#0#0#0#4001#9";
```

| # 段 | 含义 | 实拍值（云桌面） | 说明 |
|---|---|---|---|
| 1 | 版本 | `1_lbt6_03` | `1_lbt6_` 前缀 + build 号；lbt=萝卜头（飞秋作者团队） |
| 2 | 等级 | `128` | feiX 样例见 998/128 |
| 3 | MAC 地址 | `FEFFCFAFAC` | feiq 用它做自环过滤（同 MAC + 同名 = 自己的回环包） |
| 4-6 | 标志位 | `0#0#0` | feiq 作者注「其他字段是什么意思呢？」——未知，恒 0 |
| 7 | 常量 | `4001` | **不是命令字**！恒定值（早期 64B 截断样例误读为 34001） |
| 8 | 常量 | `9` | 恒定值；即冒号链首段 |

## 3. 冒号链字段

```
<version(含#私有头)>:<毫秒时间戳>:<用户名>:<主机名>:<IPMsg命令字(十进制)>:<附加段>
```

feiq 的 pack 函数（逐字引用，sep=':'）：

```cpp
os<<mVersion<<sep<<packetNo<<sep<<mName<<sep<<mHost<<sep<<cmdId<<sep;
sender.write(os);   // extra 附加段
os.put(0);          // 结尾补 \0
```

| 字段 | 实拍值（192.168.133.162） | 说明 |
|---|---|---|
| packetNo | `1793326334373` | 毫秒级 Unix 时间戳（非自增序号） |
| 用户名 | `Administrator` | Windows 登录名；可能带 `#` 尾（真昵称复合段，见 §7-待确认） |
| 主机名 | `YANFA0223` | 真实主机名（此前误读为工号） |
| 命令字 | `6291457` | 十进制！0x600001 = IPMSG_BR_ENTRY(0x01) \| 0x600000 标志位 |
| 附加段 | `许彬\0平台听\0…`（GBK） | **真昵称与组名就在这里** |

## 4. 命令字对照（冒号链第 5 段，十进制书写）

按 IPMsg 标准（`IS_CMD_SET(cmd, test) = (cmd & 0xFF) == test` 剥选项位）：

| 十进制 | 十六进制 | 标准命令 | 飞秋用途（feiX 实测） |
|---|---|---|---|
| 0 | 0x00 | BR_ENTRY 语义 | 上线广播 |
| 33 | 0x21 | RECVMSG | 消息回执（附加段=被回执包序号，feiX 样例 `2147483647`） |
| 288 | 0x120 | SENDMSG\|SECRETOPT | 发送消息（附加段=消息文本） |
| 121 / 122 | 0x79 / 0x7A | INPUTING / INPUT_END | 正在输入 / 停止输入 |
| 6291457 | 0x600001 | BR_ENTRY \| 0x600000 | **周期在线刷新包**（约 30s 一轮），附加段带昵称/组名 |
| 62914559? | (0x600001+噪声) | 同上 | 疑似同包 OCR 误读，待日志复核 |

feiq 补充的飞秋扩展命令：`IPMSG_INPUTING=0x79`、`IPMSG_INPUT_END=0x7a`、
`IPMSG_KNOCK=0xd1`（窗口抖动）、`IPMSG_SENDIMAGE=0xc0`（发送图片）。

## 5. 实拍样例逐段解析（云桌面 feilian.log）

完整在线刷新包（192.168.133.162:2425，95B，hex → 文本）：

```
1_lbt6_03#128#FEFFCFAFAC#0#0#4001#9:1793326334373:Administrator#:YANFA0223:62914559:许彬\0…
└─version(私有头)─┘              └─pktNo─┘ └─用户名─┘└─主机─┘└─命令─┘ └─GBK附加─┘
```

- 附加段 GBK 字节 `d0ed b1f2` = 「许彬」——与飞秋好友列表（许彬 YANFA0022，192.168.133.162）**完全对上**；
- `Administrator` 后的 `#`：疑为「登录名#真昵称」复合段，该机真昵称段为空（待 §8 复核）；
- 此前 64B 截断样例把 `#4001#` 误读成命令字 34001，实为私有头常量。

## 6. 编码约定

- Windows 版飞秋线上编码为 **GBK**（feiX 明确：接收和发送都需编码转换）；
- 附加段多值用 `\0` 分隔（标准 IPMsg 惯例：上线包 = `昵称\0组名\0`）；
- 用户名/主机名中不允许出现 `:`（分隔符冲突，feiX 引用 IPMsg 注意事项）；
- 文件传输走 TCP 2425，请求格式 `包序号:文件ID:偏移`（十六进制，feiq 源码 `os<<std::hex`）。

## 7. 与标准 IPMsg 的互通关系（双栈行为）

- 飞秋对外**兼容标准 IPMsg**：能解析我们的标准 BrEntry/SendMsg（此前飞秋列表出现过飞联用户）；
- 但飞秋的**周期在线包、回执等用自己的私有头**（version 带 MAC），标准解析器直接失败；
- 飞秋对标准 BrEntry（无论广播或单播）**不回标准 AnsEntry**——真昵称查询失败的根因；
- 自环过滤：feiq 用「MAC 相同 && 用户名相同」，比飞联现在的「昵称+主机名」更稳。

### 8.1 标准 IPMsg 文件传输协议规格（feiq 源码实锤）

**发送方向**：`SENDMSG | FILEATTACHOPT(0x00200000)`，附加段结构：

```
<消息文本>\0<条目1>\a<条目2>\a…\a
```

- 文本与文件区以 `\0`（ascii 0）分隔；条目间以 `\a`（ascii 7，FILELIST_SEPARATOR）分隔；
- 每条目 5 段冒号分隔：`fileId:文件名:大小:修改时间:文件类型`
  - fileId：**十进制**（发送方进程内自增）；
  - 文件名：GBK 编码，文件名含 `:` 转义为 `::`；
  - 大小/修改时间/文件类型：**十六进制**（feiq 发送侧 `os<<std::hex` 后流状态延续）；
  - 文件类型：`1`=REGULAR、`2`=DIR（目录传输时目录条目先行、后续相对路径条目跟随，拉取用 GETDIRFILES=0x62）。

**接收方向**：TCP 连发送方 2425，发送请求行后读裸流：

```
<包序号>:<文件ID>:<偏移>:\n     ← 三段全部十六进制（feiq os<<std::hex）
```

- 普通文件用 `GETFILEDATA(0x60)` 语义，目录用 `GETDIRFILES(0x62)`；
- 服务端按偏移回裸流，直至文件结束（feiq/飞秋均如此，无结束标记，靠文件大小截断）。

**飞联落地要点**：与现有自研 FLTN/1 通道并行——发飞秋用标准通道，飞联之间可保留 FLTN/1；
引擎 SendFiles 需按目标客户端类型选择协议（或统一走标准通道简化实现）。

## 9. 对飞联的改造方案（待讨论，未动代码）

`ParseFeiqNative` 升级为 v2：

1. 冒号 SplitN 7 段（version 段含 `#` 不含 `:`，天然兼容）；
2. version 段含 `1_lbt` 前缀 → 飞秋包；取私有头第 3 段 MAC 备用（自环过滤增强）；
3. `fields[1]`=packetNo（时间戳，可忽略）；`fields[2]`=登录名（`#` 后若非空 = 真昵称复合段）；
4. `fields[3]`=**真实主机名**（替代现在的「IP 充当 host」，主键回归 `昵称@主机名`）；
5. `fields[4]`=命令字：`&0xFF` 剥标志位后走标准分发——`0x01`(BR_ENTRY) 复用 upsertPresence，
   `0x20`(SENDMSG) 可走消息路径（飞秋私有无回执格式另议），`0x79/0x7A` typing；
6. `fields[5]`=附加段 GBK 解码（复用 DecodeExtra），按 `\0` 拆出**真昵称 + 组名（→部门）**；
7. 建档：`nick=附加段昵称（空则回退登录名）`、`dept=组名`、`host=真实主机名`——
   现有「Administrator@IP 占位 + 单播升级」机制整体作废（飞秋心跳自带真昵称，无需查询）。

**待真机复核**（用 feilian.log 现有样例即可确认大半）：
- [ ] 多台机器附加段是否都带「昵称\0组名」（98/135/172 等样例的 GBK 段逐台解码）；
- [ ] `Administrator#` 复合段在有人设昵称的机器上是否为 `Administrator#昵称`；
- [ ] 命令字 `62914559` 与 `6291457` 是否同包异录（OCR 噪声）；
- [ ] 飞秋 SENDMSG(288) 的附加段完整结构（真昵称发消息时的字段序）。
