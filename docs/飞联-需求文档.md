# 飞联 LANChat — 需求文档

> 版本：v0.1 草案（2026-10-29）
> 界面规范见根目录《[DESIGN.md](../DESIGN.md)》，本文只谈「做什么」，DESIGN.md 谈「长什么样」。

## 1. 项目背景与目标

「飞联 LANChat」是一个**复刻飞秋（FeiQ）功能**的局域网即时通讯软件：

- 飞秋本身**免费但闭源**，无法基于其代码二次开发；
- 飞秋完全兼容**飞鸽传书（IPMsg）协议**，而 IPMsg 是开源项目、协议公开，因此按协议自行实现即可，成品还能与飞秋/飞鸽**互发消息**；
- 目标：内网免服务器、点对点直连的聊天 + 文件传输工具，单文件 exe，替代飞秋在日常办公中的角色。

**合规边界**：只复刻功能与交互，不反编译飞秋、不使用其图标/名称/素材（功能不受版权保护）。

## 2. 用户与使用场景

- 内网/隔离网环境下的团队：办公区同一交换机下的同事互发消息、传文件、发全员广播。
- 典型流程：打开软件自动发现同事 → 点名发消息 / 双击传文件 → 右下角通知提醒 → 托盘常驻。
- 明确的**非目标**：不做外网穿透、不做账号体系、不做云端同步（局域网点对点是底线）。

## 3. 功能需求

### FR1 用户与在线发现
- 启动后向局域网 **UDP 2425 广播上线包**，收到他人广播时互相应答，维护在线用户列表。
- 定时心跳保活；退出时广播下线包；异常掉线超时判定离线。
- 用户属性：昵称、主机名、IP、部门/分组（可自定义）、状态（**在线 / 勿扰 / 离线**）。
- 支持修改自己的昵称与状态，变更即时广播。

### FR2 即时消息
- 单聊文本消息（含 emoji），UDP 直发，收发即达；失败（离线）给出提示。
- 「正在输入…」状态提示。
- 会话列表：最近会话、最后一条预览、时间、未读角标；新消息会话置顶（交互详见 DESIGN.md「ConversationRow / MessageBubble」）。
- 聊天记录：本地留存，会话内可滚动查看历史（「聊天记录」入口）。

### FR3 群聊与广播
- **局域网广播**：一条消息发往广播地址，全员可见（对应飞秋的广播功能）。
- 群聊：本地分组（把若干联系人组成一个「群」），发消息时逐一分发，界面按群会话聚合显示。
  - 说明：IPMsg 原生没有群概念，此为**自定义扩展**，仅本软件用户间生效（见 §4.3）。

### FR4 文件/文件夹传输
- 基于 **TCP 2425**：先以消息协商文件列表（文件名/大小/块编号），对方接受后建立连接分块传输。
- 支持多文件与整个文件夹（递归打包）。
- 传输卡片两种状态：进行中（实时百分比 + 速度）／已完成（「打开文件夹」直达）。
- 可选：传输完成后自动打开所在目录（默认关）。
- 兼容性备注：官方飞鸽与飞秋之间文件传输本就存在兼容问题，**与飞秋互通时消息优先保证，文件传输互通作为尽力而为项**。

### FR5 联系人
- 联系人列表按部门分组展示，含群聊与广播入口。
- 单击查看资料卡（部门/IP/主机名/个性签名），双击进入会话（交互见 DESIGN.md「ContactRow / ContactDetailPanel」）。

### FR6 屏幕截图
- 全局热键 `Ctrl+Alt+A` 呼出截图（取屏 → 选区 → 复制到剪贴板 / 直接作为图片消息发送）。
- 实现：`kbinani/screenshot` 取屏 + 自绘选区窗口；热键 `golang.design/x/hotkey`。

### FR7 远程协助（后期阶段）
- 聊天头部「远程协助」按钮，被控端确认后开始（类 VNC 的屏幕流 + 鼠标键盘事件转发）。
- 里程碑 M5 再启动，不阻塞主线。

### FR8 设置
通用（深色模式/消息通知/开机自启动/语言）、文件与传输（保存目录/自动打开/限速）、快捷键（展示与自定义）、关于。明细见 DESIGN.md「SettingsPanel」。

### FR9 通知与托盘
- 最小化到系统托盘常驻（`getlantern/systray`），新消息托盘图标变化 + 系统通知（`beeep`）。
- 勿扰状态下不弹通知，只累计未读。

## 4. 通讯协议设计

### 4.1 基础格式（IPMsg 文本协议）

```
版本号:包序号:发送者昵称:发送者主机名:命令码:附加内容
```

- 端口：**UDP 2425**（发现 + 消息）、**TCP 2425**（文件传输）。
- 命令码 = 基础命令（上线应答/发送消息/接收确认等）+ 选项位（广播/加密/锁定等），按 IPMsg 官方定义实现。

### 4.2 互通目标

| 对端 | 文本消息 | 文件传输 |
|---|---|---|
| 飞秋 / 飞鸽 | ✅ 优先保证 | ⚠️ 尽力而为（两边官方互传本就有坑） |
| 飞联 ↔ 飞联 | ✅ | ✅ 全功能 |

### 4.3 自定义扩展

- 群聊消息、正在输入、部门/个性签名等超出 IPMsg 的能力，通过**自定义命令码区间 + JSON 附加内容**实现，仅飞联之间识别；对飞秋/飞鸽退化为普通消息或忽略。
- 扩展码段需在开发时统一登记，避免与官方码冲突。

## 5. 系统架构

```
┌─────────────────────────────────────────┐
│ UI 层  Wails v2 + React 19 + Vite + Tailwind│  ← 已迁移落地，按《DESIGN.md》实现
├─────────────────────────────────────────┤
│ 事件桥（channel / Wails Events）          │  ← 单向数据流：引擎吐事件，UI 订阅
├─────────────────────────────────────────┤
│ 引擎层（纯 Go 独立 package，不依赖 UI）   │
│  ├─ discovery  UDP 广播/心跳/用户表       │
│  ├─ messaging  消息收发/群聊/广播/记录    │
│  └─ transfer   TCP 文件文件夹传输         │
└─────────────────────────────────────────┘
```

- 引擎层可独立编译为 CLI 版先行联调（M1），UI 只是它的订阅者。
- 关键坑位：Windows 下 UDP 广播必须设 `SO_BROADCAST`（`net.ListenConfig` 的 `Control` 回调加 socket option，标准库直接发会被拒）。
- 产物：**单文件 exe**（WebView2 系统自带，无运行时依赖）。

## 6. 非功能需求

- 免服务器、免账号、免配置：安装即用，全部通讯留在局域网内。
- 冷启动 < 1s，常驻内存 < 100MB，空闲 CPU ≈ 0。
- 聊天记录仅存本机（后续可选 SQLite），不上传任何数据。

## 7. 里程碑

| 阶段 | 内容 | 验收标准 |
|---|---|---|
| M1 引擎 | 协议编解码 + 广播发现 + 单聊（CLI 双端联调） | 两个进程互相发现并收发消息；与飞秋互通文本消息 |
| M2 界面 | Wails + React 骨架（UI 已迁移完成，见任务拆解 M0），按 DESIGN.md 落地三视图与聊天 | DESIGN.md 验收清单全过 |
| M3 文件 | TCP 文件/文件夹传输 + 进度卡片 | 飞联之间传 1GB 文件夹成功且可续看进度 |
| M4 体验 | 截图、托盘、通知、热键、设置、深浅色 | 日常使用无阻断 |
| M5 扩展 | 远程协助、群聊增强、聊天记录搜索 | 另行细化 |

## 8. 待定问题（开工前需拍板）

1. **互通优先级**：是否需要与飞秋完全互通？决定协议实现的保守程度（建议：文本互通，文件尽力）。
2. **聊天记录存储**：纯内存 + JSON 落盘，还是 SQLite？记录保留多久？
3. **群聊形态**：本地分组即可，还是需要邀请/退群流程？
4. **传输断点续传**：M3 是否必须，还是列入 M5？
