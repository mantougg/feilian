# M1 网络引擎 — 子任务清单

> 来源：《[飞联-开发任务拆解.md](../飞联-开发任务拆解.md)》M1 节 · 状态图例：✅ 完成 ｜ 🔶 进行中 ｜ ⬜ 未开始
>
> **目标**：两台进程互相发现、互发文本消息，并与飞秋文本互通。
> **边界**：全部改动在 `engine/` 包内（可加 `cmd/feilian-cli/`），**不碰 UI**。
> **前置**：M0 已完成（协议编解码 `engine/protocol.go` + 门面骨架 `engine/engine.go`）。
> **建议顺序**：T-M1-1 → 2 → 3 → 4 →（5/6/7 可穿插）。

## T-M1-1 UDP 监听与广播发送 ✅ <a id="T-M1-1"></a>

- [x] `engine/` 内建立 UDP socket：`net.ListenConfig` 绑定 UDP 2425
- [x] **Windows 关键**：`Control` 回调里设置 `syscall.SO_BROADCAST`（标准库直接对广播地址 WriteTo 会被拒）
- [x] 支持向广播地址 `WriteTo` 发送报文
- [x] 多网卡处理：枚举网卡取各网段定向广播地址，不能只发 255.255.255.255

**验收**：单元测试——本机两个 UDP 套接字经广播地址互收报文。✅（`TestBroadcastLoopback` 通过；实测广播回环会把包投递给同端口所有 socket 含发送者自己，已记入 T-M1-2 挂点注释）
**依赖**：无。**落点**：`engine/engine.go`（`Start()` 的 TODO(T-M1-2) 上方挂载）。

## T-M1-2 上线发现与心跳 ✅ <a id="T-M1-2"></a>

- [x] 启动即广播 `CmdBrEntry`，extra 携带 JSON（部门/状态）
- [x] 收到他人 Entry 时单播回 `CmdAnsEntry`
- [x] 每 30s 心跳 `CmdNoOperation`
- [x] 退出时广播 `CmdBrExit`（挂到 `Stop()`）

**验收**：A 启动后 B 的 peers 列表出现 A；A 退出后 5s 内 B 侧下线。✅（`TestDiscoveryAndExit` 通过，实测 0.04s；peers 列表本体在 T-M1-3 落地，本任务以 peer_online/offline 事件验证；非 JSON extra 兜底 online 有 `TestPeerOnlineToleratesPlainExtra`）

## T-M1-3 用户表与状态机 ✅ <a id="T-M1-3"></a>

- [x] peers map + RWMutex；`Peers()` 返回快照
- [x] 超时判定离线（LastSeen 距今超过阈值）
- [x] `CmdBrAbsence` 状态变更（在线/勿扰/离开）映射 `Peer.Status`
- [x] 状态变更经 `EventPeerUpdate` 推送

**验收**：`Peers()` 快照含昵称/IP/主机名/部门/状态；状态变更事件可推送。✅（`TestPeersSnapshot` / `TestAbsenceStatusUpdate` / `TestSweepTimeout` 通过；用户表主键 nick@host，同机双开靠昵称区分；超时阈值 = 3×心跳 = 90s，15s 清扫一次；未知心跳来源不建档）

## T-M1-4 文本消息收发 ⬜ <a id="T-M1-4"></a>

- [ ] `SendText(ip, text)` 直发 `CmdSendMsg|OptSendCheck`
- [ ] 收到消息即回 `CmdRecvMsg`，回执按 PacketNo 关联 → `EventReceipt`
- [ ] `BroadcastText(text)` 广播消息
- [ ] Extra 中文 UTF-8 编码验证

**验收**：双进程互发消息秒达；回执事件触发；对飞秋发消息对方能收到。
**依赖**：T-M1-1。**落点**：`engine/engine.go`（`SendText`/`BroadcastText` 已留 TODO）。

## T-M1-5 事件桥到 UI ⬜ <a id="T-M1-5"></a>

- [ ] `app.go` startup 起 goroutine：`engine.Events()` → `runtime.EventsEmit`
- [ ] 绑定方法：`GetPeers` / `SendText` / `GetSelf` / `SetSelf`
- [ ] 前端可先用日志页验证事件订阅

**验收**：前端能订阅到 `peer_online` / `message` 事件。
**依赖**：T-M1-3、T-M1-4。**落点**：`app.go`（注释已标 T-M1-5）。

## T-M1-6 CLI 联调模式 ⬜ <a id="T-M1-6"></a>

- [ ] 新建 `cmd/feilian-cli/`：不起 UI
- [ ] 终端打印引擎事件 + stdin 读入发消息
- [ ] 支持 `-nick 测试A` 参数

**验收**：`go run ./cmd/feilian-cli -nick 测试A` 两个终端窗口互发现、互发消息；作为引擎回归测试工具长期保留。
**依赖**：T-M1-4。

## T-M1-7 飞秋互通验证 ⬜ <a id="T-M1-7"></a>

- [ ] 真机装飞秋，与本程序对发文本
- [ ] 核对编码：飞秋可能 GBK，需按首包探测并转换（`golang.org/x/text/encoding/simplifiedchinese`）
- [ ] 核对 Entry/AnsEntry 兼容性
- [ ] 不互通时输出差异分析记录（存 `docs/` 下）

**验收**：与飞秋双向文本互通。
**依赖**：T-M1-4。

## M1 风险清单

1. 飞秋报文编码可能是 GBK 而非 UTF-8，需按首包探测；
2. 多网卡环境广播地址选择（枚举网卡取各网段定向广播）；
3. 防火墙首次运行需放行 UDP 2425（安装器/首启引导处理）。

## 完成出口（M1 整体验收）

两个 CLI 进程互相发现并收发消息；与飞秋互通文本消息（对应需求文档 §7 M1 验收标准）。
