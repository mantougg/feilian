# M1 网络引擎 — 子任务清单

> 来源：《[飞联-开发任务拆解.md](../飞联-开发任务拆解.md)》M1 节 · 状态图例：✅ 完成 ｜ 🔶 进行中 ｜ ⬜ 未开始

> **目标**：两台进程互相发现、互发文本消息，并与飞秋文本互通。
> **边界**：全部改动在 `engine/` 包内（可加 `cmd/feilian-cli/`），**不碰 UI**。

## T-M1-1 UDP 监听与广播发送 ✅ <a id="T-M1-1"></a>

- [x] `engine/` 内建立 UDP socket：`net.ListenConfig` 绑定 UDP 2425
- [x] **Windows 关键**：`Control` 回调里设置 `syscall.SO_BROADCAST`（标准库直接对广播地址 WriteTo 会被拒）
- [x] 支持向广播地址 `WriteTo` 发送报文
- [x] 多网卡处理：枚举网卡取各网段定向广播地址，不能只发 255.255.255.255
- [x] **端口占用自动避让**（云桌面真机排障补强）：SO_REUSEADDR 绑定被占端口会"成功"但入站包全被先绑定者截走（同机飞秋场景联系人恒空）——Start 先裸探测（无 REUSEADDR）端口占用，被占则避让到 +1..+9 并推 notice；看门狗 8 秒零收包兜底再避让一次；避让位心跳改播 CmdBrEntry 换全网 AnsEntry 刷新在线（否则 90s 误判全员离线）；广播目的端口集合补发邻近避让端口保同机多实例互见

**验收**：单元测试——本机两个 UDP 套接字经广播地址互收报文。✅（`TestBroadcastLoopback` 通过；实测广播回环会把包投递给同端口所有 socket 含发送者自己，已记入 T-M1-2 挂点注释。避让闭环：`TestStartFallsBackWhenPortTaken` / `TestFallbackInstanceStillDiscoverable`——占用方无论设不设 SO_REUSEADDR 裸探测都报被占，避让实例与标准位实例双向互见且可互发消息）
**依赖**：无。**落点**：`engine/engine.go`（`Start()` 的 TODO(T-M1-2) 上方挂载）。

## T-M1-2 上线发现与心跳 ✅ <a id="T-M1-2"></a>

- [x] 启动即广播 `CmdBrEntry`，extra 携带 JSON（部门/状态）
- [x] 收到他人 Entry 时单播回 `CmdAnsEntry`
- [x] 每 30s 心跳 `CmdNoOperation`
- [x] 退出时广播 `CmdBrExit`（挂到 `Stop()`）
- [x] **晚到者发现**（云桌面真机排障补强）：Entry/AnsEntry 只在客户端启动瞬间各广播一次，飞联后启动时长期在线的飞秋用户只剩私有命令心跳，严格按协议建档将永远错过他们（「已收 60 包 0 联系人」）——`ensurePeer` 对任何未知发送者的报文先建档（状态兜底 online），未知命令分支补刷 LastSeen 防 90s 误判离线；昵称/主机名经编码探测转 UTF-8（飞秋 GBK）；`Probe()` 手动重播探测（空态「重新探测」按钮）；Stats 增加未解析报文计数与 hex 样例（环形缓冲 8 条：时间/来源 IP/hex，空态内联展示 + 「复制诊断」按钮，并落盘 `%LocalAppData%\feilian\feilian.log`）

**验收**：A 启动后 B 的 peers 列表出现 A；A 退出后 5s 内 B 侧下线。✅（`TestDiscoveryAndExit` 通过，实测 0.04s；peers 列表本体在 T-M1-3 落地，本任务以 peer_online/offline 事件验证；非 JSON extra 兜底 online 有 `TestPeerOnlineToleratesPlainExtra`。晚到者发现：`TestUnknownCommandCreatesPeer` / `TestUnknownHeartbeatCreatesPeer` / `TestExitFromUnknownNoChurn` / `TestGBKNickDecodedOnReceive` / `TestLateJoinPlainExtra`）

## T-M1-7 飞秋互通验证 🔶 <a id="T-M1-7"></a>

- [ ] 真机装飞秋，与本程序对发文本（**需人工操作，待用户验证**）
- [x] 核对编码：飞秋可能 GBK，需按首包探测并转换（接收方向 `DecodeExtra` 已实现并带单测：UTF-8 合法性探测，非 UTF-8 按 GBK 解码；发送方向恒 UTF-8，向 GBK 对端发送的编码策略待真机确认后定）
- [x] **飞秋私有格式发现**（云桌面真机抓样实锤）：飞秋在标准 IPMsg 之外持续广播自有格式心跳（`1_lbt…#…#34001#9:<序号>[:<会话>]:<登录名>#:…`，# 与 : 混合分隔，lbt=萝卜头）——`ParseFeiqNative` 解析后按源 IP 建档（部门标「飞秋」，登录名相同的多机靠 IP 区分），云桌面「已收包 0 联系人」即因这些包此前全部落入未解析分支。样例hex与四种截断形态入 `TestParseFeiqNative`；建档/保活/全链路 `TestFeiqNativeCreatesPeers` / `TestFeiqNativeEndToEnd`
- [x] **真昵称升级**：私有格式昵称只有 Windows 登录名——占位发现后向对方单播标准 BrEntry（每 IP 一次，`queryRealNick`），飞秋按标准协议回 AnsEntry 携带自定义昵称/主机名；upsertPresence 将同 IP 占位记录静默替换为真实资料（事件先 offline 后 online，dept 为空继承不覆盖），后续飞秋心跳只刷新真记录不回退占位。`TestFeiqPlaceholderUpgrade` / `TestQueryRealNickOncePerIP`；飞秋首包完整（256B）落日志供私有格式深度逆向
- [ ] 核对 Entry/AnsEntry 兼容性（**需真机抓包比对，待用户**）
- [ ] 飞秋原生格式深度互通：真昵称/部门拉取、原生格式发消息（视发现互通后的真机效果决定）
- [ ] 不互通时输出差异分析记录（存 `docs/` 下）（视真机结果）

**验收**：与飞秋双向文本互通。🔶（引擎侧编码适配就绪；发现链路已兼容飞秋私有格式心跳；真机互通须人工安装飞秋并对发验证，无人值守无法完成——建议用户执行：本机装飞秋 → `wails dev` 或 CLI 与飞秋对发文本 → 反馈结果，不互通时提供飞秋侧现象以便差异分析）

## M1 风险清单

1. 飞秋报文编码可能是 GBK 而非 UTF-8，需按首包探测；
2. 多网卡环境广播地址选择（枚举网卡取各网段定向广播）；
3. 防火墙首次运行需放行 UDP 2425（安装器/首启引导处理）。

## 完成出口（M1 整体验收）

两个 CLI 进程互相发现并收发消息；与飞秋互通文本消息（对应需求文档 §7 M1 验收标准）。
