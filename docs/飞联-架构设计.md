# 飞联 LANChat — 架构设计

> 需求见《[飞联-需求文档.md](./飞联-需求文档.md)》，UI 规范见根目录《[DESIGN.md](../DESIGN.md)》，任务索引见《[tasks/INDEX.md](./tasks/INDEX.md)》。
> 本文回答「怎么设计的、为什么这样设计」：架构分层、协议、数据流、关键技术决策。

## 1. 系统定位

复刻飞秋（FeiQ）功能的局域网即时通讯软件：**免服务器、免账号、点对点直连**，兼容飞鸽传书（IPMsg）协议，可与飞秋/飞鸽互发文本消息。产物为**单文件 Windows exe**（WebView2 系统自带，无运行时依赖）。

明确不做：外网穿透、账号体系、云端同步。

## 2. 技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 桌面壳 | Wails v2.17（Go 1.26） | 单文件 exe、WebView2 零依赖；Go 侧直接跑网络引擎 |
| 前端 | React 19 + Vite + Tailwind 4 + TypeScript | UI 源自 React 原型项目（lanchat）整体迁移，聊天组件手写、不引 admin 组件库 |
| 协议 | 自实现 IPMsg（UDP/TCP 2425） | IPMsg 开源、协议公开，实现即可与飞秋互通 |
| 动效 | motion（framer-motion 后继）+ CSS | 克制的入场/弹窗动效，`prefers-reduced-motion` 关闭 |

## 3. 分层架构（核心约束）

```
┌─────────────────────────────────────────┐
│ UI 层  Wails WebView（React，frontend/src）│  只订阅事件、调绑定方法
├─────────────────────────────────────────┤
│ 事件桥（app.go + Wails Events）           │  单向数据流：引擎吐事件，UI 订阅
├─────────────────────────────────────────┤
│ 引擎层（engine/ 纯 Go，不依赖 UI 与 Wails）│
│  ├─ protocol.go  IPMsg 编解码/命令码       │
│  ├─ engine.go    门面：发现/消息/用户表     │
│  └─ transfer/    TCP 文件传输（M3）        │
└─────────────────────────────────────────┘
```

三条铁律：

1. **引擎层可独立编译**：`engine/` 包不得 import Wails 或任何 UI 依赖；CLI 联调模式（`cmd/feilian-cli`，T-M1-6）就是这句话的验收手段。
2. **单向数据流**：引擎不感知 UI，通过 `chan Event`（缓冲 ≥ 64）吐事件；`app.go` 在 startup 起转发 goroutine，把通道事件 `EventsEmit` 给前端；前端只读事件 + 调用绑定方法（`SendText`/`GetPeers`/`SetSelf`…），绝不反向直接写引擎内部状态。
3. **UI 只是引擎的订阅者**：mock 数据全部退场后（M2），UI 自身不持有网络真相，只持有渲染状态（未读、置顶等派生量，集中在 `utils/chatLogic.ts` 纯函数计算，带单测）。

## 4. 通讯协议设计

### 4.1 线上格式（UDP 2425，文本协议）

```
版本号:包序号:发送者昵称:发送者主机名:命令码:附加内容
```

- 附加内容可含冒号，解析只切前 5 个字段（`strings.SplitN(raw, ":", 6)`）。
- 命令码 = 基础命令 + 选项位按位或（如 `CmdSendMsg|OptSendCheck`）。
- 编解码权威实现在 `engine/protocol.go`（前端 `utils/ipmsg.ts` 仅为参考/测试镜像）。

### 4.2 命令码分配

- 官方码（0x0000–0x00FF 基础 + 选项位）：`NoOperation` 心跳、`BrEntry`/`AnsEntry`/`BrExit` 上下线、`BrAbsence` 状态、`SendMsg`/`RecvMsg` 消息与回执、`ReadMsg`/`DelMsg` 已读/撤回、`OptFileAttach` 文件附加。
- **飞联扩展码段**：`CmdFeiLinkTyping = 0x00001001`、`CmdFeiLinkGroupMsg = 0x00001002`。扩展码仅飞联识别，对飞秋/飞鸽退化为普通消息或被忽略；新增扩展码必须先在 `protocol.go` 登记注释，避免与官方码冲突。

### 4.3 发现与保活

启动广播 `BrEntry`（extra 携带 JSON：部门/状态，飞联扩展）→ 收到他人 Entry 单播回 `AnsEntry` → 每 30s `NoOperation` 心跳 → 退出广播 `BrExit`；超时未见判离线。

### 4.4 文件传输（M3）

UDP 协商（`SendMsg|OptFileAttach`）→ 对方接受后走 **TCP 2425**。飞联之间沿用 `FLTN/1 <fileID>` 与扩展文件清单；对飞秋按其 `\0`/`\a` 清单及 `packetNo:fileID:offset:` 请求行兼容，文件传输仍为尽力而为项，优先保证飞联 ↔ 飞联全功能。

### 4.5 互通兼容策略

- 文本互通优先保证；文件传输尽力而为。
- 飞秋报文编码可能为 GBK：按首包探测，必要时经 `golang.org/x/text/encoding/simplifiedchinese` 转换（T-M1-7 落实）。

## 5. 并发模型

- 引擎内部：UDP 收发循环 goroutine + 心跳定时器；`peers map` 由 `sync.RWMutex` 保护，`Peers()` 返回快照而非引用。
- 事件出口：单一 `chan Event`（`engine.New` 传入），UI 侧只有一个消费者（app.go 转发协程），避免多处订阅竞态。
- 生命周期：`Stop()` 用 `sync.Once` 关闭 quit channel 结束内部循环。

## 6. 前端架构

- **三视图模型**：消息 / 联系人 / 设置，右侧主区与中列成对切换；聊天对话框只存在于消息视图（防串态的关键约束，验收清单第 1 项）。
- **宿主桥接**：`lib/wailsBridge.ts` 统一收口所有 `window.go.main.App` 调用；纯浏览器 `npm run dev` 时优雅降级（假窗口边框演示形态），`isDesktop()` 区分两种形态。
- **主题**：CSS 变量 + `light-dark()`，默认跟随系统；标题栏按钮与设置开关双向同步；主色靛蓝 `#4f46e5`/`#7c7ff2`，状态色在线绿/勿扰红/离线灰。
- **纯函数逻辑层**：置顶、未读、预览等会话派生逻辑在 `utils/chatLogic.ts`（单测覆盖），组件只做渲染与交互，M2 接引擎时逻辑层零改动。

## 7. 关键技术决策与坑位记录

| # | 决策/坑位 | 说明 |
|---|---|---|
| 1 | **Windows UDP 广播必须设 `SO_BROADCAST`** | 经 `net.ListenConfig` 的 `Control` 回调加 socket option；标准库直接对广播地址 WriteTo 会被拒（T-M1-1 核心要点） |
| 2 | **多网卡广播地址** | 枚举网卡取各网段定向广播地址，不能只发 255.255.255.255，否则多网卡机器发现不全 |
| 3 | **防火墙** | 首次运行需放行 UDP 2425，首启引导/安装器处理（M4 收尾） |
| 4 | **单文件 exe** | `wails build` 产出（当前 11.6MB），WebView2 系统自带 |
| 5 | **性能预算** | 冷启动 < 1s、常驻内存 < 100MB、空闲 CPU ≈ 0；心跳间隔与超时判定参数须以此为约束 |
| 6 | **隐私边界** | 聊天记录仅存本机（JSON 或 SQLite 待定 §8-2），不上传任何数据 |
