# 飞联任务开发

按固定流程「领取 → 读上下文 → 实现 → 验收 → 回写」执行任务。**一次只做一个任务**（用户明确要求批量时除外），不做顺手重构。

## 第 1 步：定位任务

1. 读 `docs/tasks/INDEX.md`（任务总索引与进度仪表盘）。
2. 用户给了任务 ID（如 T-M1-3）→ 直接定位到对应清单小节；未指定 → 选**状态 ⬜ 且依赖全部 ✅** 的最靠前任务（M1 建议顺序：T-M1-1 → 2 → 3 → 4 → 5/6/7 穿插）。
3. 任务命中「待定问题」（飞秋互通深度 / 记录存储形态 / 群聊形态 / 断点续传，见 INDEX §5）时，先向用户确认结论再动手，不要自行拍板。

## 第 2 步：读上下文（不要跳过）

| 读什么 | 为什么 |
|---|---|
| `docs/tasks/M*-*.md` 对应小节 | 子步骤 checklist + 验收标准 + 落点文件 |
| `docs/飞联-开发任务拆解.md` 对应行 | 实现要点与风险 |
| `docs/飞联-架构设计.md` §3 架构铁律及关联章节 | 保证改动不越界 |
| 需求文档的对应章节 / 根目录 `DESIGN.md`（UI 任务必读） | 功能与交互基准 |
| 落点文件现有代码 | 风格对齐；`engine/engine.go` 内有 TODO(T-M1-x) 挂点注释 |

## 第 3 步：领取（状态改 🔶）

三处同步：任务清单标题、`docs/tasks/INDEX.md` 任务行、《飞联-开发任务拆解.md》总表行。

## 第 4 步：实现

- 遵守 `AGENTS.md`：`engine/` 纯 Go（禁止 import Wails/UI）；引擎事件只经 `chan Event` 单向流出；中文注释；新增扩展命令码先登记 `engine/protocol.go`。
- Windows UDP 广播必须经 `net.ListenConfig` 的 Control 回调设置 `syscall.SO_BROADCAST`，直接 WriteTo 广播地址会被拒。
- 拉包前确认 `GOPROXY=https://goproxy.cn,direct`（默认代理不可达）。
- 实现某 TODO 挂点后删除对应 `TODO(T-M1-x)` 注释；代码风格（命名、注释密度）与所在文件一致。

## 第 5 步：测试与验收

- 改了 Go：`go test ./engine/...`；改了前端：`cd frontend && npm run lint && npm run test`。
- M1 任务用双进程联调验证：T-M1-6 完成前可写临时测试程序，完成后统一用 `go run ./cmd/feilian-cli -nick 测试A`（两个终端）。
- 对照任务清单「验收」行**逐条核对**；全部满足才可标 ✅。环境无法验证的项（如需真机飞秋、双开 exe）如实告知用户，请其验证或降低验收口径，不要默默跳过。

## 第 6 步：完工回写

1. 勾选任务清单内完成的子步骤 checkbox。
2. 状态改 ✅，三处同步（同第 3 步）。
3. 实现与文档有出入时：UI 改动同步根目录 `DESIGN.md`，架构变化同步 `docs/飞联-架构设计.md`，任务口径变化同步任务清单，避免文档失真。
4. 向用户报告：做了什么、验证结果（附测试输出摘要）、未能验证的项、建议的下一任务。

## 红线

- 验收不通过不标 ✅；测试失败如实报告，不掩饰。
- 不反编译飞秋、不使用其图标/名称/素材（合规边界，需求文档 §1）。
- 涉及待定问题先问用户；一次只做一个任务。
